# EasyLine — 2.4.4

Версия по согласованным макетам: компактный каталог «ПП-фастфуд», страница протокола с описанием и заявкой, выбор корпоративных обедов с вводом количества. По запросу пользователя блок «Меню по дням» и ссылка на пример дня удалены. Факты о протоколе показаны подписями и значениями без капсул. Фильтры сохраняются при возврате из корзины; черновик заявки — при чтении политики в том же сеансе.

Состав блюда плавно раскрывается и закрывается. Крестик внизу справа появляется с вращением; после закрытия фокус возвращается к кнопке раскрытия. Режим уменьшенного движения отключает переходы.

На главной переходы к меню обедов и каталогу ПП-фастфуда оформлены одинаковыми бордовыми кнопками. Раз в 7 секунд проходят мягкий блик и движение стрелки; при наведении кнопка поднимается на 2 px. Режим уменьшенного движения отключает эффекты.

Ветка разработки: `codex/customer-experience-2026-10-17`. Локальный просмотр: http://127.0.0.1:4190/. Основа — 2.3.3 (`88da608`); снимок для сравнения находится в `../work/customer-experience-2026-10-17/baseline-2.3.3.tar.gz`. Визуальная проверка описана в [design-qa.md](design-qa.md).

GitHub Pages использует ветку `version-2.2.3`: [открыть сайт](https://moseskm98-code.github.io/easyline-site/). Канонический адрес в метаданных: [easyline.club](https://easyline.club/).

Главная представляет три направления: протокол на 28 дней, 13 корпоративных обедов и ПП-фастфуд из 26 позиций. Каталоги имеют поиск, категории, фильтры начинки и цельнозернового хлеба. Общая корзина сохраняет только ID блюд и количество, поддерживает изменение количества и синхронизацию между вкладками.

**Цены и условия оформления нового заказа ещё не предоставлены.** Фотографии для всех 39 позиций созданы по материалам пользователя; под 38 предварительными изображениями стоит подпись «фото, состав и подача уточнить». Они не выдуманы. Корзина и экран оформления доступны для просмотра; отправка нового заказа и оплата отключены. Протокол сохраняет существующую отдельную заявку в EasyLine ERP. Реальные заявки при проверке не отправлялись.

## Исходники

- `src/page.html` — оболочка и сохранённые страницы протокола, производства, доставки, контактов и документов.
- `src/home.html`, `src/catalogs.html`, `src/cart-pages.html` — новые страницы.
- `src/product-card.html`, `src/quantity.html` — общие элементы.
- `src/site-logic.js`, `src/retained-content.js` — поведение и сохранённый контент.
- `src/customer-state.mjs` — параметры фильтров в URL и проверка количества.
- `src/catalog.json` — 39 позиций с изображениями. `priceRub` пока равен `null`.
- `src/cart.js` — фильтры, проверка корзины, хранение и расчёт известной стоимости.
- `assets/menu-refresh.css` — стили новых элементов на основе текущей палитры и шрифтов.
- `assets/customer-experience.css` — адаптивные стили согласованных макетов.

`index.html`, HTML маршрутов, sitemap, runtime метаданных и модуль `assets/menu-catalog-<hash>.js` генерируются. Их не редактируют вручную. Новые изображения назначают только после сопоставления с предоставленными фото.

## Сборка и проверка

```bash
node scripts/sync-static-site.mjs
node scripts/verify-static-site.mjs
node --test tests/*.test.mjs
```

Требуется Node.js 18+. Перед подключением оформления нужны подтверждённые цены, наличие, условия доставки и оплаты, а также интеграция приёма заказов. Юридические документы сохранены; перед публикацией новых направлений нужно проверить их применимость к новому способу заказа.

## Публикация

Перед отправкой запускают три команды проверки выше. Ветки `main` и `version-2.2.3` обновляют без переписывания истории. После успешного Pages deployment проверяют публичные каталоги, изображения, ссылки и корзину; реальные заявки не отправляют. Для обновлённых CSS используется версия в URL, чтобы старый кэш не возвращал прежний цвет ссылок.

В версии 2.3.1 отключены скрытие секций до прокрутки, повторное проявление, параллакс и задержка первого экрана. Контент виден сразу после отрисовки; состояние ошибки загрузки сохранено.

В версии 2.3.2 добавлен отдельный assets/gentle-motion.js: однократный сдвиг секций на 8 px за 200 ms и параллакс только фотографий до ±6 px внутри рамок. Контент всегда виден; старый scroll reveal остаётся отключённым. prefers-reduced-motion отключает новые эффекты.

В 2.3.3 эффект усилен по запросу пользователя: сдвиг 20 px за 360 ms, параллакс до ±14 px (до 6% высоты на маленьких фото), overscan 1.14. Секции начинают движение у края экрана, оставаясь полностью видимыми.
